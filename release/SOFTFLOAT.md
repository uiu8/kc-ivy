# kc-ivy-kpw3 使用说明

这是给 KPW3 旧 soft-float 固件使用的独立完整版本。目标环境是 KPW3 / 5.16.2.1.1（4097470002），公开资料显示它使用 ARMv7 soft-float。项目没有这台设备，首次使用必须完成现场兼容性验收。

## 使用前提

- Kindle 已越狱，并能通过 USB 磁盘运行 `documents` 下的 `.sh` 文件，或已安装可运行该扩展的 KUAL。
- 设备没有被 Calibre 以 MTP 方式连接。本版本安装阶段只接受 USB 磁盘。
- 测试者先备份个人设备资料，并保留 `cc.db`、任务、快照和回执。
- 这是独立产品包，不要把它与主线 kc-ivy 混装，也不要把单台设备的结果推广到所有旧 Kindle。

## 推荐顺序

1. 安装插件后，从主线或旧 KC 转入时在设备维护中安装 KC 0.7.0。仅升级电脑插件且已使用相同 KC 0.7.0、设备与固件及验证状态未变化时，无需重复安装或验证。
2. 弹出 Kindle，运行“KC检查运行环境”。KUAL 用户也可以选择菜单中的“检查运行环境”。
3. 重新连接，在首次使用页点击“读取环境报告”，或打开 kc-sync/logs 中最新的 KC环境检查报告。若 ENVIRONMENT_PASS 不为 1，停止并反馈报告。
4. 安全弹出，运行“KC刷新收藏夹”，重新连接并再次读取状态。
5. 在电脑端准备能力测试并选定已索引书籍；安全弹出后在 Kindle 运行“KC验证编辑能力”，重连读取结果，完成六步小样本测试：建架、改名、加入、移除、再次加入、带成员删架。每一步都要看到回执确认，且书籍文件仍存在。
6. 只有六步全部确认后，才测试真实任务。先用一两本无关紧要的书和一个新收藏夹。

## 结果怎么判断

`ENVIRONMENT_PASS=1` 只表示 Shell、备用或系统 SQLite、必要字段和辅助程序检查通过；它不表示 `/change` 已经可用。

六步测试全部有确认回执，且重复执行不会重复改变收藏关系，才可以确认“该设备组合通过当前版本验收”。任一步失败，都应保留失败任务和日志，停止重试，交给维护者分析。不要直接编辑 `/var/local/cc.db`，也不要使用旧 Kindle Collections 的 JSON 去绕过 KC 的回执链路。

报告会省略书名、令牌、序列号和数据库行内容。提交报告时，同时说明设备型号、完整固件号、连接方式、是否使用 KUAL，以及失败发生在诊断、刷新、验证还是执行阶段。

## 已知边界

备用 SQLite 是为旧 soft-float 用户空间编译的静态 ARM 程序，目标 ABI 是 `arm-linux-musleabi`。它不能保证设备支持当前数据库 schema、`/tmp/session_token`、`127.0.0.1:9101/change` 或现有启动器。KPW3 真机、PW5 以外的 SQLite 能力和旧固件执行服务都仍待现场证据。

本版本不启用 MTP，不修改主线标签，不覆盖既有发布附件，也不包含越狱过程或第三方启动环境。
