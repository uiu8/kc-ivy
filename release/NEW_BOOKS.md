# 新书直接整理：kc-ivy 1.0.26 / KC 0.6.15

## 操作

1. 安装 kc-ivy 1.0.26；设备端已有 KC 0.6.15 时无需再升级。已有设备身份和能力验证仍有效时，无须因本次升级重复初始化。
2. 通过 Calibre 或其他工具把原生支持的书籍文件传入 Kindle 的 documents 目录，等待传输结束。
3. 打开 kc-ivy 或点击“读取设备状态”。新书显示“待设备识别”，可加入收藏夹，也可由所选 Calibre 列生成归属。仅新增书籍时，原草稿保留。
4. 生成修改预览并发送，安全弹出，然后运行“KC执行收藏夹任务”。不需要为新书提前进行一次刷新和重连。
5. 重连接收回执。已确认操作按原规则回填；未索引、文件变化或匹配不唯一的项目在任务结果中说明，可重新读取后恢复剩余操作。

设备收藏状态来自上次快照；在 Kindle 上另行修改过收藏时仍需刷新。这里取消的是传新书所需的额外往返，不是取消设备状态校验。

## 实现

USB / 实验性 MTP 独立遍历 documents，跳过链接目录、隐藏目录与 .sdr 资源；候选扩展名为 AZW、AZW3、MOBI、PRC、KFX、PDF、TXT。已有原生快照记录不受扩展名限制。未索引 EPUB 不作为候选。

存在有效 Calibre 书单时保留唯一的书库 UUID 关联；否则作为设备独有候选。临时标识由设备实例、路径和 SHA-256 生成，不再依赖 Calibre UUID，也不代表 Kindle 原生编号。旧编号仅在指纹吻合时衔接。MTP 可复用同一文件列表缓存的指纹，但发送前强制重验。首次发现大量未索引文件会增加读取耗时，MTP 尤其明显；读取窗口显示进度并允许取消扫描。

仅涉及新书的任务使用 request/v2，携带路径、大小、SHA-256。Kindle 端只读查询 cc.db，用唯一的 Entry:Item 路径定位内部 UUID；提交给原生 /change 的内容只含真实编号。文件指纹不符时不执行该书操作。整批最多额外等待索引五秒，仍未索引的项目报告冲突。

执行前后的状态摘要统一映射回任务临时标识，因此原预览的状态前提仍接受核验。映射与任务记录一起持久化，pending 日志也保存该映射；中断后只读核验，不重放不确定写入。result/v2 返回映射，电脑端将已确认关系和列基线转换为真实 UUID。未包含新书的任务继续使用 v1。

新任务首次发送需要已安装 KC 0.6.14 或更新版本；旧设备端不会执行不认识的 v2 协议。已发送任务仍应使用支持其协议的运行版本，不要在待执行 v2 任务期间回退至旧 KC。

## 边界

- kc-ivy 1.0.16 / KC 0.6.15 起也支持实验性 MTP 新书流程，详见《MTP新书实验说明.md》；尚无 KPW6 真机验收。
- 不强制触发或修改 Kindle 系统索引，不按书名猜测，不修改书籍内容。
- 新书身份校验需要在电脑及 Kindle 读取涉及文件的内容；因此新书任务会增加文件读取耗时，旧书任务不做这项校验。
- 本地模拟执行、协议与回填测试不能替代真机验收；尚未在用户 Kindle 执行这版新书流程。
